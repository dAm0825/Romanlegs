## 录制前准备

1. 使用演示账户 `test` 登录，提前完成一次可疑消息检测、两轮情景演练和一次安全挑战，确保成长记录页有数据。
2. 浏览器缩放建议设置为 90% 或 100%，关闭无关标签页、通知、聊天软件弹窗和包含密钥信息的终端窗口。
3. 提前确认 DeepSeek 网络可用；若现场网络不稳定，不中断录制，可说明系统会自动切换到本地规则与预置场景。
4. 录制分辨率固定为 1920×1080，鼠标移动保持平稳，点击后停留 1 至 2 秒，方便评委看清页面反馈。
5. 建议直接使用本文旁白作为字幕，不改写专业名词，保证口播和字幕一致。

## 一、开场与技术栈介绍（00:00—00:50）

**画面操作**

从系统首页开始录制，保持页面完整，鼠标停在“智能反诈训练系统”主标题下方。

**普通话旁白**

各位评委老师好，下面演示我们的参赛作品“智能反诈训练系统”。

大学生接触到的刷单返利、冒充客服、冒充公检法、校园贷和虚假投资等骗局，往往不是一句“不要转账”就能防住。对方会制造紧急感、代入身份，并持续施压。本系统把反诈教育拆成“识别、解释、示范、演练和复盘”五个环节，帮助用户不仅知道风险，还能够说出正确的拒绝方式。

技术实现方面，前端采用 Vue 3 和 Vue Router 构建多页面单页应用，使用原生 CSS 和 SVG 完成响应式界面与雷达可视化；后端使用 Python 标准库提供轻量 HTTP 和 JSON 接口；AI 部分接入 DeepSeek `deepseek-chat`，并结合本地规则引擎、中文词项加权的轻量 RAG 检索和确定性安全复核；用户数据使用 localStorage 保存，密码通过 Web Crypto 加盐哈希处理。

AI 在本项目中不是单独的聊天按钮，而是贯穿“风险解释、情景演练和智能咨询”三个核心任务。接下来我会结合实际操作，分别展示这三处 AI 能力。

## 二、首页与交互式诈骗雷达（00:50—01:35）

**画面操作**

向下滚动到首页训练情报台，依次点击雷达中的“刷单返利”“屏幕共享”“虚假投资”风险点，展示右侧说明、案例数量和“查看案例”“练一次”按钮。

**普通话旁白**

首页上方是产品核心入口。下方的训练情报台不是静态装饰，而是一个可交互的校园诈骗雷达。

每个风险点都对应真实的训练数据。例如点击“虚假投资”，右侧会显示该类骗局的典型套路、相关公开案例数量和安全判断，并可以直接进入已筛选案例或对应演练场景。

这种设计让用户从首页就能完成一次“发现风险、查看依据、进入训练”的闭环，而不是只浏览宣传文字。

## 三、可疑消息检测（01:35—02:30）

**画面操作**

进入“风险检测”，点击“刷单兼职”示例，再点击“开始风险检测”。检测详情弹窗出现后，先展示风险等级、可疑原句和行动建议；勾选前两项行动，让进度条变化。

**普通话旁白**

接下来演示可疑消息检测。我选择系统内置的刷单返利消息，点击开始检测。

检测结果会先以独立窗口展示。上方是风险级别和风险类型，中间标出“垫付”“账户冻结”“屏幕共享”等高危原句，右侧给出可以逐项核对的行动建议。

用户完成行动后可以看到核对进度。需要深入查看时，再点击“查看完整报告”，避免一次把所有信息堆在同一页面上。

检测过程采用规则引擎和智能模型协同工作。规则负责稳定识别垫付、验证码、共享屏幕、安全账户等确定性风险；模型负责把风险解释得更自然、更适合当前语境。输入中的手机号、邮箱、证件号和银行卡号会先在本地脱敏。

## 四、风险报告与案例参照（02:30—03:20）

**画面操作**

进入完整报告页，先展示左侧风险分和触发信号；切换到“案例参照”，展示知识条目和相似真实案例；再切换到“行动清单”，展示停止转账、联系银行、保留证据和报警等步骤。

**普通话旁白**

风险报告页把结果拆成三个层次。

“风险诊断”说明为什么可疑；“案例参照”展示本次判断关联的安全知识和公开新闻；“行动清单”告诉用户下一步具体做什么。

这里需要强调，风险分数是训练中的相对判断，不是警方或银行的正式结论。系统保留原句、来源和行动步骤，用户可以看到结论是怎么得出来的。

如果模型暂时不可用，页面仍然可以根据规则和本地知识库返回风险类型、关键证据与基础处置步骤，保证核心训练流程不中断。

## 五、真实新闻案例（03:20—03:55）

**画面操作**

进入“真实案例”，切换“冒充公检法”分类，展示案例来源、发布日期、损失金额和“本案警示”。指向一条案例的原文按钮，说明点击后会打开公开新闻。

**普通话旁白**

为了避免虚构故事削弱可信度，系统收录了十一条来自官方媒体和公安机关的公开案例，并进行分类整理。

每条案例保留来源、日期、损失金额、核心套路和教育重点，点击卡片可以查看新闻原文。系统只摘录与防骗教育有关的事实，不复制整篇报道，也不对具体案件作法律判断。

## 六、多轮情景压力演练（03:55—05:15）

**画面操作**

进入“情景演练”，选择“高薪兼职”。输入“我不会垫付，也不会共享屏幕，请通过官方平台联系我。”，展示“对方发起话术、用户明确拒绝、对方再次追问”的完整对话及右侧即时复盘。

点击一条快捷安全话术，继续完成第二轮回复，展示安全分、紧张度和反馈变化。

**普通话旁白**

知道风险不等于能够在压力下作出正确反应，因此系统提供多轮情景演练。

这里选择高薪兼职场景。我方明确表示不会垫付，也不会共享屏幕。可以看到，对方没有结束对话，而是继续用“第一单真的返钱”和“先试一下”来降低警觉。

智能模型会结合当前场景和历史对话生成下一轮施压内容，让演练接近真实通话。

系统会记录用户的回复，判断是否出现验证码、屏幕共享、转账或贷款等配合动作，同时识别“不转账”“官方核验”“挂断电话”等防御性表达。右侧即时复盘会解释风险，并给出更安全的替代话术。

页面上方还展示模拟来电、通话时间和紧张度。安全分提高，紧张度下降；如果用户答应转账或共享屏幕，安全分会降低。这样形成的是可以重复练习的行为反馈，而不只是一道选择题。

进入“成长记录”，展示综合防骗力环图、最近十四天训练活跃度、检测次数、演练平均安全分、风险类型分布与能力徽章。

**普通话旁白**

成长记录页将检测、演练、挑战和学习进度转换为综合防骗力。

左侧展示训练次数和连续训练天数，右侧是十四天活跃度。用户还可以看到自己的高频风险类型和能力徽章，从而知道下一步应该重点练习什么。

当前版本的训练记录保存在本地浏览器中，不上传真实聊天内容和社交关系。它更适合校园内快速体验和课堂演示。

## 八、反诈智能助手与来源引用（05:55—06:55）

**画面操作**

进入“智能助手”，输入“客服让我开启屏幕共享来完成退款，我应该怎么处理？”。等待回答后，展示“参考知识”和新闻案例链接。

继续追问“如果我已经共享了几分钟，接下来还要做什么？”，展示第二轮回答和止损步骤。

**普通话旁白**

当用户需要连续咨询时，可以进入独立的反诈智能助手。

我询问客服要求共享屏幕退款应该怎么处理。助手先给出停止操作、拒绝共享和通过官方入口核验的建议，同时展示本次回答使用的知识条目和公开案例。

接着继续追问：“如果我已经共享了几分钟，接下来还要做什么？”可以看到第二轮回答会根据上下文补充关闭共享、联系银行止付、修改密码和保留证据等步骤。

助手采用本地知识检索增强。系统先把问题与十五类反诈知识、十一条公开案例进行匹配，再把有限资料交给智能模型组织回答。前端展示来源，用户可以判断回答依据是否可信。

## 九、AI 技术亮点与架构总结（06:55—07:35）

**画面操作**

此处可以切换到技术文档第三页的信息架构图，或者使用后期制作的架构字幕页。依次高亮“规则引擎”“本地脱敏”“知识检索”“DeepSeek”“安全复核”五个环节，再返回系统首页。

**普通话旁白**

本项目的 AI 技术亮点可以概括为四个部分，并分别服务于风险检测、情景演练和智能助手三个页面。

第一，规则引擎与智能模型双通道：确定性风险不依赖模型随机发挥。第二，本地检索增强：回答只基于反诈知识和公开案例，并展示来源。第三，安全边界：敏感信息先脱敏，模型不得索取密码、验证码，异常时自动降级到本地能力。第四，确定性评分复核：对用户的危险动作和防御性表达再次判断，纠正模型可能出现的误评分。

在具体业务中，DeepSeek 用于风险解释、动态角色扮演和助手问答；规则、检索与复核则保证这些 AI 输出有来源、可控制、可在网络异常时降级。这套结构兼顾演示可用性、结果可解释性和校园场景中的隐私要求。
